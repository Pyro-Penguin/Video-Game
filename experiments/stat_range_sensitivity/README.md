# Proposed Endgame Stat-Range Sensitivity Experiment

This experiment translates the team's proposed Level-100-equivalent stat bands into explicit, reproducible test fixtures. It extends—not replaces—the four-candidate damage equation comparison.

**Status:** Synthetic investigation only. No stat range, damage equation, move-power range, or HP target is approved.

## Team proposal represented

| Attribute | Proposed band | Experiment treatment |
|---|---:|---|
| Attack / Special Attack | 200–400+ | Attack fixtures use 200–400 |
| Defense / Special Defense | 200–350+ | Defense fixtures use 200–350 |
| Vitality / HP | 250–500+ | KO test points use 250, 350, 500 |
| Speed | 100–400+ | Recorded as out of scope; no turn-order model |

The script deliberately uses bounded endpoints for a finite sweep. The team's plus signs mean the proposal allows values above those bands; this first pass does not model those tails.

## Run

From the repository root:

```bash
cd experiments/stat_range_sensitivity
python3 stat_range_sensitivity.py
python3 -m unittest -v
```

The script writes `report.json` beside itself. Use `--output /path/to/report.json` to choose another destination.

## Experiment design

Five synthetic archetypes cover balanced, offensive, defensive, high-pressure, and low-pressure Attack/Defense pairs. Each is evaluated at Levels 1, 25, 50, and 100; move powers 40, 80, 100, 120, and 160; and Vitality points 250, 350, and 500.

All four existing candidate families are reused with their existing shared anchor calibration:

- A: direct multiplicative ratio.
- B: offset ratio with c=100.
- C: level-scaled structure.
- D: bounded offense share.

The report contains:
- Raw damage, integer-floored damage (minimum 1), raw hits-to-knockout, and integer-floor hits-to-knockout for every archetype / level / power / candidate / Vitality combination.
- One-stat-at-a-time Attack and Defense sensitivity at requested +5%, +10%, and +20%.
- Direct level-effect rows for each candidate.
- Explicit assumptions and limitations.

Damage and KO thresholds use exact rational arithmetic. Requested percentage stat changes are converted back to integer stats by truncation. Both raw and integer-floor KO counts are reported. Integer flooring is applied once per successful hit, with a minimum of 1 damage; this isolates the effect of per-hit flooring but is not a final damage pipeline because modifiers, RNG, shields, multi-hit behavior, and damage application remain excluded.

## Important interpretation limits

- The stat bands came from a team proposal and are not confirmed project data.
- Archetypes are illustrative points, not creatures, class templates, or outputs of the 70-point allocation concept.
- Move powers and levels are inherited comparison fixtures, not selected game ranges.
- No Vitality formula, stat progression, damage modifiers, type effectiveness, RNG, shields, multi-hit behavior, or simultaneous damage application is included. Integer flooring is modeled as an isolated per-hit sensitivity only.
- Speed requires a separate turn-order experiment; it cannot be judged from damage output.
- Candidate C directly includes level; A, B, and D do not. The experiment isolates that difference but does not prove which progression model is preferable.
- A passing test suite verifies implementation properties, not game balance.

## Review sequence

1. Review `report.json` generated by the script (CI validates its schema/counts but does not commit generated output).
2. Compare archetype damage sensitivity and KO bands across candidates.
3. Decide whether the proposed bands are useful enough to keep as provisional design targets.
4. Separately decide whether direct level scaling is wanted in story mode. Competitive normalization to Level 100 makes any direct level term constant within that mode.
5. Only then narrow equation families and define a target pacing envelope.

Do not select a candidate automatically from the lowest or highest KO count. The intended tactical pacing and desired counterplay must determine acceptable outcomes.
